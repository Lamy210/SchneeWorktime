# Journal v2候補の破損拒否回帰

Journal v2候補を独立読込する際、SQLite自体が開けることとアプリケーションとして信頼できることは異なる。

## 新規テスト
- **シーケンス不正**: revision=1の候補でイベント番号を2へ変更し、`invalidSequence`として拒否する。
- **余剰イベント**: revision=1の候補に連続した2番目のイベントを追加し、1件だけを黙って採用せず拒否する。
- **未知schema**: `user_version`を3へ変更し、旧候補として誤解釈せず`unsupportedSchema`として拒否する。

各テストでは不正候補の内容が検証により自動修復・変更されないことも確認する。

これらはオフライン検査の回帰試験であり、ファイルの真正性証明や本番DB採用を許可するものではない。自動移行・schema-1原本更新・CIルール変更は実施しない。
