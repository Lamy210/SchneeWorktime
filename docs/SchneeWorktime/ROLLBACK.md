# 正常DBの限定ロールバック（開発中）

対象は現行DBが正常に読め、現行・候補とも未終了勤務がなく、候補が同じepochの厳密な過去journal prefixである場合だけ。任意バックアップの復元や破損DBの置換ではない。

1. previewRollback はバックアップを検証し、現行と復元後の勤務日数・保存版を返す。書込みなし。
2. 呼び出し元が明示確認し、アプリの書込み・通知を停止し、所有者専用ディレクトリ内の新規退避先を確保する。
3. commitRollback は確認したデータを再検証し、現行の正常な論理バックアップを退避・再読込照合してから、SQLite内のCASで新epochへ原子的に切り替える。退避失敗は置換しない。
4. 旧controller・確認案・通知予約は破棄して再構成する。今回のPRは保存層のみで、UI・通知制御・破損DB原本の物理退避は未接続。

別epochのバックアップを拒否するため、論理reset後の旧世代をこのAPIで復活させない。ただし新epochへの切替後は退避した旧epochのデータも同じAPIでは戻せない。汎用復元の世代ポリシーは別途設計する。外部exportの削除や物理消去は行わない。

退避は平文JSON、電源断時のディレクトリ永続化・ACL・祖先パス・同一UIDの改変耐性は未保証。CAS競合では安全側に倒し、作成済み退避ファイルを残す。障害注入・macOS CI・実機確認は未完了。
