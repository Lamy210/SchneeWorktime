# Journal退勤用予約枠（暫定対策・BUG-01）

## 契約
active勤務の残2イベントを必要な観測と退勤に予約する。残2件では新規観測・退勤のみ、残1件では退勤のみが新規保存できる。重複観測は従来どおりno-opであり、退勤時に必要な観測を省略しない。既存の10,000件、16MiB上限、100件の開始/再開停止は維持する。既存journalの再生には新しい受付制約を適用しない。

この制約は共通commit経路で検証するため過去日訂正もactive中に予約枠を消費できない。明示的な拒否ではDBを変更しない。エラー時に現行DesktopModelが記録停止/再読込を要求する既存の安全動作を維持する。警告UIを追加するが個々の操作の事前無効化は未実装。

## 検証と残リスク
Store境界試験2件を追加。残3から2への予定変更、残2で予定/休憩拒否、残1で重複観測no-opと新規観測拒否、直接退勤と再読込で既存の不確実性保持を確認する。最新CI未確認。これはStore直接操作の検証であって、拒否された観測があるApplicationがそれを無視して退勤できるという意味ではない。

複数回の新規観測、既に満杯のactive勤務、16MiB・ディスク枯渇は救済しない。一定の退勤枠を確保しても終了を保証できず、容量拡張と移行設計をP0として残す。自動リセット・履歴削除・上限緩和なし。状態が確認できなければ記録停止と原本保全を優先する。
