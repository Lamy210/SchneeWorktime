# 起動不能時の読取専用履歴保全（BUG-01 / P0）

通常のWorktimeController初期化は観測の保存とcheckpoint更新を要求する。容量枯渇でこれが失敗しても、アプリが保存フォルダの排他ロックを保持する場合に限り、明示選択された別の所有者専用ディレクトリへ既存のschema-1 JSONを出力できる経路を追加する。

SQLite READONLYとquery_onlyを使用。DB新規作成・BEGIN IMMEDIATE・観測更新・復元・resetを行わない。元のepoch/revision/payloadと全履歴を通常のバックアップ検証器で検証する。checkpointは従来のJSON形式と同じく含めない。ディレクトリ外への非上書き公開を行う。WALヘッダや-journal/-wal/-shmが存在する場合、破損・未知形式・未来記録・権限異常では拒否する。保存フォルダ全体の原本保全を優先する。

原本の書込み権限を外したDBからの取得、完全bytes一致、上書き拒否、補助ファイル拒否、欠落・破損・同一フォルダ拒否の回帰試験を追加。CIと実機は未確認。既存の同一ユーザー内の排他・ファイルidentity境界が前提であり、敵対的な同一ユーザーによる競合を保証しない。論理保全でありファイル全体のバックアップではない。上限到達済みactive勤務を退勤可能にする移行は未実装。リリース判定NO-GOを維持する。
