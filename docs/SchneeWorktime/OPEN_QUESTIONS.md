# 未確定事項・採用条件

| 論点 | v0.4暫定値 | 確認/次のアクション |
|---|---|---|
| フレックス清算期間 | 法定残業の計算を行わない | 就業規則を確認して別changeで設計 |
| 基準終業時刻 | 18:00、ユーザー変更可能 | 実際の基準時刻と通知要否 |
| 休憩予定時間帯 | 未指定、残り必要量だけ予測 | 時間帯予約が必要なら後続MVP拡張 |
| 実際の休憩 | 手動開始/終了 | 会社の休憩記録方法との整合性を要確認 |
| 通知OS時刻保証 | best effort | スリープ・Focusモード実機QA |
| 継続勤務中の設定変更 | 次の勤務日から。active適用は確認必須 | UXレビュー |
| 端末スリープ中の勤務 | 既存状態は保持、要確認表示 | 非推測のまま訂正導線を検証 |
| 終了日と再開時の帰属 | 明示的に同一勤務日へ再開 | 複数日に跨る例の確認 |
| 正式な残業の表示 | MVPでは実装しない | 清算期間規則の裏取り後に追加 |
| パネルのデフォルト前面固定 | OFF | スペース/フルスクリーン実機UX |
| 配布 | 未決定 | templateの署名・公証を自動有効化しない |

## v0.3補足
- スリープ中に勤務が継続したかはOSでは特定できない。未確認としたうえで明示確認または区間訂正を許可する。
- 実働7時間の事前予約通知は計算上の予測。アプリが停止中に実働達成を確定することはできない。
- 通知の発火と取消が競合するため、既に配信された通知の完全取消は非保証。
- 会社のフレックス清算期間、休憩義務や正式な残業の計算は依然として未確定でありMVPには含めない。

## v0.4 追加確認事項
- アプリ非稼働の観測間隔: 最後にアプリが生存していた時刻は勤務の証拠ではない。観測間隔と持続書き込み頻度は実機の省電力計測後に決める。
- 当日の休憩予定変更UI: 残り休憩予定の明示上書き（予測のみ）、解除でプロファイル既定に戻す。過去の休憩履歴を変更しない。
- 未確認区間: 実働下限/上限から到達の確実性と到達時刻の範囲を区別する。OSは勤務継続の事実を認定できない。
- 翌日再開: 暦日ではなくWorkday UUIDを指定する。後続勤務日が存在する場合は追加再開せず訂正する。
- 会社規則: コアタイム/清算期間/正式な残業/休憩義務・時刻は確認が必要。法定残業/賃金はMVPで計算しない。
- NFR: 起動時間、常駐メモリ、CPU、バッテリー使用率、OS通知配送は未実測。PoC後に合格閾値を決定する。

## v0.4.1 補足
- 未確認の中断時間は「勤務」「実際の休憩」「非勤務ギャップ」の3分類が必要。非勤務ギャップは記録済み休憩を増やさない。
- 当日の将来休憩予定上書きは入力時点での残り休憩を意味する。実績として取得した休憩で残りを消費し、0未満にしない。

## v0.6の判断
- 予定休憩を将来の退勤時刻に入れられない場合、試算は`infeasible`。利用者が明示的に休憩予定を変更するまで自動短縮しない。
- 既定通知を「休憩込み退勤見込みの15分前」、最短到達は別カテゴリの任意通知とする。
- 休憩記録が所定/法定の時間と整合するかは本人の記録と就業規則を確認する必要がある。アプリだけで合法/違法を認定しない。
- 明示的に保存した退勤予定が予定休憩と矛盾する場合のUIは「予定変更が必要」と表示する。本人の意思として予定を残せても、実現可能な退勤予測として扱わない。
