# 勤務記録の障害時保全・復旧手順

対象: macOS 15以降のSchneeWorktime開発版。正式な勤怠記録の復旧を保証するものではない。

## 判断

| 状況 | 対応 |
|---|---|
| 正常DB・同一epochの過去の終了済みjournal | 明示確認付き限定ロールバック |
| 時刻・権限・別プロセスの問題 | 原本を保全し原因を解消して再読込 |
| DB破損・消失、別epoch/別DBのバックアップ | 保全と読み取り専用検証に留める。自動置換は未対応 |
| バックアップにも不整合がある | 使用を中止。記録を推測して作成しない |

## 原本の保全

1. 打刻を停止する。既存記録がある場合に新規DBを作成しない。
2. アプリを終了し、同一保存先を使う他のSchneeWorktimeプロセスやSQLite操作が停止していることを確認する。
3. Finderの「フォルダへ移動」で `~/Library/Application Support/` を開く。
4. `SchneeWorktime` フォルダ全体を、所有者専用の新しいローカルフォルダへコピーする。既存フォルダに上書きしない。worktime.sqlite、存在するWAL/SHM/rollback journal、session.lockを含め、原本は変更しない。コピーの完了、ファイル一覧、サイズを確認する。保存先を公開・クラウド同期しない。
5. 原本・保全コピーを保持する。session.lockを削除したり、SQLiteを強制修復したり、OSの保護機構を無効化したりしない。

ファイルシステムの障害でコピーが失敗する場合は、追加書込みを避けて専門家へ相談する。コピーは論理整合性の保証ではない。

## 通知と再読込

- 記録や時計を確認できない場合、アプリが排他ロックを保持していれば所有通知の取消対象とする。既配信の通知は回収できず、異常終了時の取消は保証されない。
- 必要に応じてmacOSの通知設定からSchneeWorktimeの通知を無効化する。障害が解消するまで通知を根拠に打刻しない。
- 時計・権限・排他起動の問題を解消後、既存データの再読込を選ぶ。エラーが続く場合、原本の上書きや新規作成は行わない。

## バックアップ確認と限定ロールバック

- 読み取り専用のバックアップ確認で日数、revision、訂正数、未終了勤務の有無を確認する。
- 復元可能なのは正常DBかつ同一epoch・厳密な過去journal prefix・双方終了済みの場合のみ。[限定ロールバック](ROLLBACK.md)を参照。
- 復元前に現在の正常な論理履歴を別ファイルへ保全する。旧epochは復元後に再適用できない。保全ファイルを削除しない。
- 破損DB・別epoch・別DBへの復元は、削除済み履歴を復活させない世代ポリシーと原本の保護を別途設計するまで行わない。

## リリース用障害試験（未実施）

隔離したテストアカウントとダミー履歴で確認し、実データを使用しない。

| 試験 | 成功条件 |
|---|---|
| DB破損/読取エラー | 打刻停止、既存DBを初期化しない、復旧案内 |
| 既存通知ありの読取失敗 | 所有通知のみ取消対象、再予約なし |
| 以前の終了済みバックアップ | 明示確認前は書込みなし |
| 保全先の権限/容量エラー | 現行履歴を変更せず停止 |
| 通知取消未収束 | 復元不実行 |
| 保全成功後のCAS競合 | 現行履歴を上書きせず保全ファイル保持 |
| 復元中にアプリを強制終了 | 再読込で旧または新しい整合した世代を取得し、中途半端な履歴を確定しない |
| 過去世代・別DB・未終了勤務 | 拒否 |
| 復元後の再起動 | 履歴・監査・epochを確認、未来通知のみ再評価 |

試験結果にはsource SHA、OS、architecture、操作、ログと残存リスクを記録する。実機で全条件を確認するまでは完了扱いにしない。

## 現在のDB内の履歴初期化（全ファイル消去ではない）

メニューの「現在のDB内の勤務記録を削除」で対象件数と未終了勤務、保存revisionを確認し、「削除」と入力する。所有通知の予約取消が収束しない場合は中止する。現在のDBの論理履歴・監査・観測情報を一体で初期化し、別epochにする。外部に保存したファイルや別コピー、SSD上の残存痕跡は削除保証の対象外。既配信通知の回収も保証しない。異常終了後は再読込し、旧または新世代を確認する。内部backup/診断データの完全な削除範囲・中断注入・実機確認は未完了。

## DBファイルの権限・リンク拒否

新規DBは0600で排他的に作成する。既存DBとSQLite sidecarは所有者・通常ファイル・単一リンク・group/other非公開を毎接続前に確認し、SQLiteもNOFOLLOWで開く。旧版で作成された0644等のDBは自動変更せず停止する。アプリを終了し、原本全体を保全したうえで所有者・リンク・ACLを確認し、正当なDBと付随ファイルだけを所有者専用権限に修正して再読込する。リンク先へのchmodや自動削除は行わない。祖先パス・ACL・同一UIDによる並行差替えに対する完全な保証ではない。実機と最新CIは未確認。
